> 狀態：**historical** — Slice 0–8 已全數完成（tag `v1.1-retrieval-optimizer`）。

與 [requirements](v1.1-retrieval-optimizer-requirements.md)、[architecture](v1.1-retrieval-optimizer-architecture.md) 一致。本檔不加入 requirements 未核准的新功能；所有 Acceptance Criteria 皆可映射到下列 Slice。

## 切分原則
每個 Slice：**可獨立驗證、明確輸入輸出、有測試、不破壞 v1.0、有停止條件**。硬限制門檻一律 **[TODO:Slice0]**（由 Slice 0 baseline 推導，不憑空填）。標記：**[MVP]** 必做 /**[Optional]** 可延 v1.2 /**[Future]** 後續版本。

### 與使用者建議切法的差異（說明理由）
沿用 Slice 0–8 骨架，微調兩點：
1. **Provenance / Canonical Document 前置到 Slice 1**（原提示未明列）：evidence-span 判定依賴 canonical offset 與 identifiers，必須先於 Trial Runner 與 retrieval。
2. **Embedding cache 併入 Slice 3**：它是 chunking 搜尋的效能前提，與 `ChunkingStrategy` 同步落地最自然。

其餘與建議切法一致。名稱 `Slice 4` 由「Exact-code / Hybrid」明確為「Identifier-aware Retrieval（candidate union）」。

## Slice 0 — Baseline 與失敗案例固定化 [MVP]
- **Scope**：跑現有 evaluation，固化目前 metrics 為 baseline；把 E102/D900、精確識別碼不穩、Top-5 重複等**已知失敗案例**寫成回歸樣本；由 baseline 推導硬限制預設值；將 `evaluate_retrieval.py` 的 `build_services`/`ingest_samples`/`evaluate`/`threshold_report`/`_percentile`/`_summary` 抽成可 import 模組（`__main__` 保留為薄包裝）。
- **Files/modules affected**：`evaluation/evaluate_retrieval.py`（抽模組，行為不變）；新增 `evaluation/optimizer/`（或 `app/optimizer/`）套件初版與 baseline 快照檔（JSON）。
- **Migration**：無。
- **API**：無。
- **Tests**：baseline 快照回歸測試；抽模組後既有 eval 輸出不變（對照 `docs/reports/results.json` 結構）；失敗案例（E102 top-1 現況）以測試固定。
- **Acceptance**：baseline metrics + 失敗案例快照可重現；硬限制預設值有 baseline 依據（填入 requirements §8.4 的 [TODO:Slice0]）。
- **Risks**：**低風險**（非零）— 抽模組可能造成 regression；以「輸出不變」測試防護。
- **需真實 LLM**：否。**付費/限額 API**：否。

## Slice 1 — Eval Case / Evidence Span Schema + Canonical Document + Provenance [MVP]
- **Scope**：定義 eval case schema（§requirements 6.1）；`CanonicalDocumentBuilder`（版本化 normalized text、PDF page-local offset、MD/TXT doc-global + `canonical_text_version`、`paragraph_index`）；`IdentifierExtractor`（index-time 抽取 + 正規化，`identifier_normalization_version`）；chunk payload 補 `char_start`/`char_end`/`paragraph_index`/`identifiers`/version 欄位（非破壞）；`EvidenceMatcher`（offset overlap / section-page / anchor / 多 span → Level 2/1/0）。
- **Files/modules affected**：`app/services/document_loader.py`、`app/services/pdf_loader.py`、`app/models/document_element.py`（加 offset/paragraph_index）、`app/models/chunk.py`（`to_payload` 加欄位）、`app/services/vector_store.py`（`identifiers` keyword index）；新增 `canonical_document.py`、`identifier_extractor.py`、`evidence_matcher.py`；新 eval dataset 檔（擴充 `evaluation/questions.json` → 新 schema，保留舊檔對照）。
- **Migration**：Qdrant payload 新欄位（舊 point null 相容）+ `identifiers` keyword index；SQLite `schema_migrations` + `eval_cases` 表。
- **API**：無（case CRUD 於 Slice 7/8）。
- **Tests**：canonical 版本化（規則變更 bump version）；PDF page-local vs MD/TXT doc-global offset；identifier 正規化（見 Slice 4 案例）；EvidenceMatcher 各判定路徑 + 多 span；payload 非破壞（舊 point 查詢仍正常）。
- **Acceptance**：可用原文來源範圍標註且對位穩定；chunk 邊界改變不影響 relevance 判定；v1.0 `/api/query` 行為不變。
- **Risks**：offset 對位（尤其 PDF）；以 anchor fallback + 版本警示緩解。
- **需真實 LLM**：否。**付費/限額 API**：否。

## Slice 2 — 隔離 Trial Runner + Metrics [MVP]
- **Scope**：`TrialRunner`（建隔離 collection `optimizer_<run_id>_<trial_id>`、記錄 config/hash/version、可中斷恢復、失敗隔離）；`MetricsCalculator`（全 metrics + 三層 graded relevance + Graded NDCG 不可計算標示 + near-dup 判定）；結果寫 SQLite + JSON。
- **Files/modules affected**：新增 `trial_runner.py`、`metrics.py`；`app/repositories/`（或新 `optimizer_repository.py`）加 `eval_runs`/`trials`/`trial_metrics`/`trial_results`；重用 `IndexingService`/`RetrievalService`。
- **Migration**：SQLite 新增 4 表。
- **API**：無。
- **Tests**：以 conftest Fakes + `FakeRetrievalService` 驗每個 metric（含 NDCG 不可計算、near-dup、graded level）；trial 失敗隔離（一 trial error 不影響他者）；中斷恢復（重跑跳過已完成 trial）。
- **Acceptance**：能對單一 config 產出完整 metrics + 每題 Top-5 明細；Case D 的比較資料就緒。
- **Risks**：metric 定義歧義 → 以 requirements §8 為單一真相來源。
- **需真實 LLM**：否。**付費/限額 API**：否。

## Slice 3 — Chunking Search Space + Embedding Cache [MVP]
- **Scope**：`ChunkingStrategy` 介面 + 實作（fixed token window / paragraph-aware / heading(section)-aware；chunk size/overlap；是否含 section title；是否保留鄰段上下文）；`EmbeddingCache`（content-hash keyed，key=normalized chunk text hash + model）。
- **Files/modules affected**：新增 `chunking_strategy.py`、`embedding_cache.py`；`app/services/text_splitter.py`（包成一個 strategy 實作）；`app/services/embedding_service.py`（外掛 cache，不改預設行為）；surface `candidate_multiplier`/`candidate_cap` 等到 config。
- **Migration**：無（cache 為檔案/記憶體層，不影響正式 schema）。
- **API**：無。
- **Tests**：不同 chunking 策略產出符合預期（含 title、鄰段）；cache 命中（相同 chunk text + model 不重算）；cache 不因 query-time 參數失效。
- **Acceptance**：可掃描 chunking 搜尋空間且重複內容重用向量；chunking trial 明顯加速。
- **Risks**：cache key 正規化不當 → 過度/不足命中；以測試界定 key 規則。
- **需真實 LLM**：否。**付費/限額 API**：否（整合測試用**本機** BGE 模型，非付費）。

## Slice 4 — Identifier-aware Retrieval（candidate union）[MVP]
- **Scope**：query-time `IdentifierExtractor`（與 Slice 1 共用、同 version）；`RetrievalStrategy`（介面，預留 sparse）identifier-aware 實作：dense candidates ∪ `identifiers` keyword exact-match candidates → 依 `document_id + chunk identity` 去重 → exact boost + confusable penalty → final Top-K；正規化規則記入 Trial Config。
- **Files/modules affected**：新增 `retrieval_strategy.py`；`app/services/retrieval_service.py`（作為 dense 基底或並存）；`app/services/vector_store.py`（keyword exact-match 查詢）。
- **Migration**：無（沿用 Slice 1 的 `identifiers` index）。
- **API**：無（策略經 trial config 選用）。
- **Tests（至少涵蓋）**：
  ```text
  E102 / e102 / E-102 → 正規化為 E102
  CX-500 vs CX500     → 是否同義須明確定義並測試
  同一 chunk 含多個代碼
  真正代碼結果未進 dense Top-K，但經 identifier candidate union 被找回   ← 關鍵 recall 測試
  E102 不被語意相近的 D900 搶先
  ```
- **Acceptance**：Case A（Exact-code）成立：含正確代碼 evidence 者優先、且 union 能救回未進 dense Top-K 的正確結果；confusable error rate 可量測。
- **Risks**：正規化定義（CX-500/CX500）需明確且版本化，避免暗改；boost/penalty 權重列為 trial 維度而非硬編。
- **需真實 LLM**：否。**付費/限額 API**：否。

## Slice 5 — Optimizer Search Strategy [MVP]
- **Scope**：`OptimizerService`：Baseline Trial + 可重現 Grid/Random Search（固定 seed）；套用硬限制 → 依 MRR/Relevant Section Precision@5/Recall@5 排序 → 輸出 **Pareto Frontier**；tune/validation/test group-aware split；產出報告（JSON + Baseline/Candidate diff 資料）。BO 僅保留介面 [Future]。
- **Files/modules affected**：新增 `optimizer_service.py`、`search_space.py`、`report.py`；CLI 進入點（`evaluation/optimizer/run.py` 或 `python -m ...`）。
- **Migration**：無。
- **API**：無（CLI 產出，API 於 Slice 7/8 只讀）。
- **Tests**：同 seed → 同結果（可重現）；硬限制正確篩除（退化/誤命中候選被擋）；Pareto 正確性；split group-aware（同 group 不跨 split）。
- **Acceptance**：Case B（不退化）、Case C（不誤命中）由硬限制保證；能選出通過限制的 best candidate 且輸出 Pareto 而非單一總分。
- **Risks**：搜尋空間過大 → 先 Grid 小網格 + Random 補樣；過擬合 → test 不參與搜尋 + 樣本數揭露。
- **需真實 LLM**：否。**付費/限額 API**：否。

## Slice 6 — Human Review（最小 HITL [MVP] / Active Sampling [Optional]）
- **Scope [MVP]**：LLM 從文件章節產生**候選**問題 + 建議 query type → 人工**接受/修改/刪除**才進 dataset（同源同 `group_id`）；evidence-span 標註（CLI/前端表單）。**[Optional]**：找差異最大 / 最不確定 / 最混淆案例、主動要求選來源、依新標註自動重跑 optimizer。
- **Files/modules affected**：新增 `candidate_question_generator.py`（用既有 `llm_client.py`）、`review` 流程；`eval_cases` 的 `review_status`/`source_origin`；（前端於 Slice 8）。
- **Migration**：無（沿用 `eval_cases`）。
- **API**：`POST/PATCH /api/optimizer/evaluation-cases`（Slice 7/8 落地）。
- **Tests**：候選題產生以 **mock LLM**（沿用 `FakeLLMClient`）；未接受候選不得進 dataset；group_id 防洩漏；LLM 不得自評通過（無「系統已通過」路徑）。
- **Acceptance**：候選題須人工確認才入庫；標註可用 evidence span；LLM 僅建議。
- **Risks**：LLM 幻覺候選 → 一律人工把關；限額 API 節制呼叫。
- **需真實 LLM**：是（候選題產生；可用 Groq/OpenAI-compatible）。**付費/限額 API**：是（少量、可 mock 測試，不做大量請求）。

## Slice 7 — Apply / Rollback [MVP]
- **Scope**：首次 alias migration（`factory_knowledge` → 建 `factory_knowledge_active` alias → 應用改走 alias → 重驗 v1.0）；`AliasManager`（atomic switch）；Apply 流程（驗 candidate/dataset/corpus/commit、stale 拒絕、建 versioned collection、readiness 驗證、切 alias、保留舊 collection）；Rollback（顯示目前/目標、確認、切回）；`AuditLog`。
- **Files/modules affected**：新增 `alias_manager.py`、`audit_log.py`、`app/api/optimizer.py`（Apply/Rollback + 只讀 endpoints）；`app/services/vector_store.py`/`dependencies.py`（查詢改指 alias）；SQLite `apply_audit` 表。
- **Migration**：Qdrant 首次 alias 建立；SQLite `apply_audit`。**這是唯一觸及正式索引結構的 Slice —— 僅建立 alias 指向現有 collection，不改資料、不重建。**
- **API**：`GET /api/optimizer/runs*`、`/comparison`、`POST /candidates/{trial_id}/apply`、`POST /rollback`。
- **Tests**：alias 首次 migration 後 `/api/query` 不變；atomic switch + rollback；拒絕未確認 / stale candidate / 未通過 readiness；audit 記錄完整。整合測試需真實 Qdrant（隔離 collection）。
- **Acceptance**：Case E 成立：確認後才套用、可回滾、有 audit、stale 被拒。
- **Risks**：切 alias 時序 / readiness → 嚴格順序 + 失敗不切；避免刪舊 collection。
- **需真實 LLM**：否。**付費/限額 API**：否。

## Slice 8 — Frontend / Docker / Demo / README [MVP]
- **Scope**：前端第 4 tab「Retrieval Optimizer」：Eval cases 數量與 split、Baseline 指標、Trial 狀態、候選比較、Best Candidate、指標差異、**相同問題 Top-5 實際差異**、需人工判斷案例、Apply 按鈕、Rollback 狀態、目前 alias / 目標 collection。前端**只讀** CLI job 報告 + 觸發 Apply/Rollback（經 API），不直呼 Qdrant。Docker/README/demo 更新（README 更新於實作階段，本規劃階段不改）。
- **Files/modules affected**：`app/static/index.html`（第 4 tab + `#panel-optimize`）、`app/static/app.js`（複製 retrieve 流程 + 重用 `renderSourceCard`）、`app/static/styles.css`；`docker-compose.yml`（不加 worker/broker）。
- **Migration**：無。
- **API**：消費 Slice 7 endpoints。
- **Tests**：前端手動/煙霧驗證 + API 契約測試（回應結構）；Top-5 diff 呈現正確；Apply 需確認欄位。
- **Acceptance**：能看到相同問題在 Baseline 與 Candidate 下 Top-5 差異（非只顯示最佳分數）；Apply/Rollback 可從 UI 觸發並顯示 alias 狀態。
- **Risks**：vanilla JS 手刻複雜比較表 → 若過於複雜再評估小型工具（本版不導入框架）。
- **需真實 LLM**：否（前端）。**付費/限額 API**：否。

## Slice 相依與建議順序
```text
Slice 0 ─► Slice 1 ─► Slice 2 ─► Slice 3 ─► Slice 4 ─► Slice 5 ─► Slice 7 ─► Slice 8
                                   └──────── Slice 6 (最小 HITL，可與 5/7 並行；Active Sampling 可延) ──┘
```
- **建議第一個 Slice**：**Slice 0**（低風險，提供回歸基準與硬限制推導依據）。

- Slice 7 為唯一觸及正式索引結構者（僅建 alias），需最謹慎。
